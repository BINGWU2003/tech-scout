# 阶段 2 前端接入与手工验收

2026-09-06：阶段 2 研究主链页面和配套轻量接口已实现，构建、静态检查与后端接口检查已执行。**浏览器操作、视觉检查和页面交互验收由用户执行，当前尚未标记通过。**

## 1. 范围与入口

登录后从侧栏「技术研究」进入 `/research`，新建研究后进入 `/research/:projectId`。同一项目的不同轮次使用 `?runId=...`，支持刷新和链接定位。

- 研究列表显示当前账号最近 100 个项目，不新增删除、重命名或历史对比功能。
- 研究详情显示步骤、状态、版本、预算、事件、错误、取消和手动重试。
- 计划提供领域、年份、关键词、排除词、CPC 和筛选理由表单，最多 3 个方向。确认后锁定；新一轮重新规划并使用独立预算。
- 仅 Planner 失败时可手工填写计划。其他节点失败只能手动重试或取消；重试不重置原预算。
- 实体审核逐项暂存、跨页保留，再一次提交所有待确认项。未选择项不会默认确认，可明确将剩余项标记为跳过。草稿只保存在当前组件，离开页面或刷新会丢失，界面已说明。
- 结果保留后端原始排序，展示推断、专利引用、授权年份计数、身份依据、缺失项及冲突。引用直接打开本次专利快照；公司详情另设「查看最新目录资料」链接，不混用实时 Catalog 作为历史依据。
- 上传、连续追问、报告、Markdown 导出和完整阶段 3 工作台不在本次范围。

本次不修复[真实后端验收](./phase-2-acceptance-2026-09-06.md)发现的组织类型准入、相关性排序、样本外推问题。页面简短提示局限，不在前端隐藏大学或重新排序来掩盖问题。

## 2. 启动

已有数据库迁移无需重跑。本次没有增加表或修改 Python 协议。

在项目根目录分别打开三个终端：

```powershell
uv run --project services/intelligence python -m tech_scout_intelligence
```

```powershell
pnpm --filter @tech-scout/api dev
```

```powershell
pnpm --filter @tech-scout/web dev
```

按 Vite 输出的地址访问并登录。访问域名、IP 和端口应与 `apps/api/.env` 中的 `WEB_ORIGIN` 一致，写入请求依赖 Origin 和 CSRF。若已有服务运行，重启相应进程加载新代码即可，避免重复占用端口。

历史验收项目属于独立验收账号，普通登录账号看不到是预期的所有权隔离；使用自己的账号新建研究即可。单纯查看历史页面和快照不发模型请求，新建研究、确认计划及主动重试可能产生真实调用。

## 3. 用户浏览器验收清单

| 操作                                             | 预期                                                                           |
| ------------------------------------------------ | ------------------------------------------------------------------------------ |
| 登录后打开技术研究；尚无项目时查看列表           | 导航可达、空状态明确、可输入问题                                               |
| 输入问题并创建；网络不稳定时保持问题不变再次提交 | 按请求 ID 复用项目，不能重复创建或重复计费；失败时可刷新项目列表确认已保存记录 |
| 等待 Planner                                     | 可见步骤与预算；在待确认计划处暂停，不自动执行后续筛选                         |
| 编辑计划、增删方向、输入非法年份或过多关键词     | 正常字段可编辑，约束错误明确；最多 3 个方向，年份不能超出当前发布范围          |
| 确认计划                                         | 计划锁定，运行进入筛选；重复点击不能重复提交                                   |
| 执行时断网再恢复                                 | 提示实时连接断开，SSE 重连并补取事件，摘要轮询兜底；不会自动重试模型           |
| 刷新研究详情、切换历史轮次再回来                 | 从服务端恢复已保存状态；链接中的轮次仍准确，计划不会被重新确认                 |
| 若出现待确认主体，逐项查看并暂存、翻页           | 草稿保留；确认需选已有公司和支持证据；无证据不能强行确认                       |
| 标记「跳过剩余项」，检查后统一提交               | 已选择项保留，其余明确跳过，全部决定一次提交；Catalog 不受修改                 |
| 完成后打开企业、引用专利、工作集分页、身份冲突   | 使用本次快照，可见来源与哈希；点击引用直接定位对应专利                         |
| 点击「查看最新目录资料」                         | 明确离开历史快照，跳到该公司当前 Catalog 页面                                  |
| 无结果或运行失败                                 | 原因可见，不自动放宽条件或继续下一节点；允许有意义的手动操作                   |
| 取消本轮                                         | 先明确确认，取消后不能继续此轮；原记录与费用保留                               |
| 创建新一轮                                       | 新问题和新预算，原轮次保留并可切换                                             |
| 切换登录账号、直接输入他人的研究链接             | 不显示上个账号缓存；他人资源无法读取或操作                                     |
| 窄屏、长公司名、键盘 Tab/Enter/Escape、深浅主题  | 布局可读、控件可操作、弹窗可关闭，不遮挡确认按钮                               |

真实数据可能不会触发所有分支：当前版本大量未知主体已有离线终态，零新增待确认项是正常结果。不要为触发界面测试改写日常 Catalog。失败、确认和预算边界的系统行为另有后端自动化覆盖。

若由用户运行现有前端自动化，`pnpm --filter @tech-scout/web test` 会启动 Playwright 浏览器。本次未运行该命令，也没有使用浏览器工具代替用户验收。

## 4. 配套接口与数据边界

共享契约位于 `packages/contracts/src/research-view.ts`，NestJS 新增 `/api/v1/research/ui`：

| 路径后缀                                       | 内容                                                              |
| ---------------------------------------------- | ----------------------------------------------------------------- |
| `GET /runs/:id`                                | 摘要、计划、预算、可选领域和待确认 ID；不返回 artifacts           |
| `GET /runs/:id/events`、`GET /runs/:id/stream` | 轻量事件、序号、状态和节点，支持 after / Last-Event-ID            |
| `GET /runs/:id/result`                         | 最多 10 个原排序主体、引用、缺失项与统计                          |
| `GET /runs/:id/patents`                        | 快照专利分页，可按 companyId 或 patentId 过滤                     |
| `GET /runs/:id/candidates`                     | 待核验主体分页，可筛选需处理项                                    |
| `GET /runs/:id/candidates/:candidateId`        | 身份依据与快照公司选项；支持依据提示仅作辅助，Python 仍作最终校验 |
| `GET /runs/:id/companies/:companyId`           | 公司身份、关系、来源与人工确认依据                                |
| `GET /runs/:id/conflicts`                      | 身份差异和关系审核冲突分页                                        |
| `POST /runs/:id/actions`                       | 复用原动作处理与幂等逻辑，仅将响应改为轻量摘要                    |
| `POST /projects/:projectId/runs`               | 同项目新轮次，返回轻量摘要                                        |

列表和创建项目继续复用原 `/research/projects` 接口。所有新接口继承登录、所有权、输入验证和写入 CSRF；动态 ID 使用参数化查询。状态/事件通过 SQL 投影避免取回完整 JSON，详情按需从已保存工作集读取并只返回白名单字段。原接口、内部 Python→NestJS 事件和数据库原始快照保持不变；本次解决的是页面传输，不宣称已优化内部事件存储。

浏览器研究区域采用独立、按账号重建的 QueryClient；运行流按序号去重，运行结束或离开组件时清理连接，执行中保留每 5 秒摘要轮询。历史事件分页读取，界面显示最近 100 条。表单输入、外部标题和来源均按普通文本渲染。
