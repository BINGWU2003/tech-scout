## 3. 内容质量发现

### 3.1 研究范围和排序过宽

当前多个方向之间为 OR，工业视觉与 AI 硬件专利取并集。排序按最高领域规则分、相关专利数量、最近年份决定，不要求公司同时具备两个方向的依据。结果偏向大型通用硬件主体，不能直接当作“工业质检边缘推理产品公司”名单。

| 2    | 삼성디스플레이(주)                          | 58             |
| 3    | INTEL CORPORATION                           | 31             |
| 4    | 에스케이하이닉스 주식회사                   | 28             |

| 9    | QUALCOMM INCORPORATED                       | 8              |

这些是程序原始输出，不代表已人工认可其业务适配性。后续应区分核心应用条件与辅助技术条件，并记录主体跨方向覆盖；排序不能只依靠宽领域规则分和专利数量。

### 3.2 身份匹配成功不等于公司类型成立

`UNIVERSITY OF DAYTON` 被输出为 `catalog_verified`。快照显示其 GLEIF 主体存在，正式关系为 `gleif_exact_name_country`、`auto_accepted`，但该候选没有独立审核决定。当前程序复用正式关系，未另行核验主体是否为商业公司。

这说明 LEI/名称国家匹配只能支持法律主体身份，不能保证组织类型为公司。应补组织类型依据与名单准入规则，不能只按名称字符串删除个案。本次保留原始结果和 Catalog，未在线改写审核结论。

### 3.3 引用有效不代表解释充分

IBM 的引用 `10388015` 标题为 `Automated septal defect detection in cardiac computed tomography images`，实际是心脏 CT 缺损检测。排除词 `medical/patient/diagnos` 没有覆盖这一表述，模型仍写了“可能与工业视觉质检相关”，属于依据薄弱的关联。

此外，Evidence 当前每家公司只提供按专利 ID 排序的前 5 条标题/CPC。模型对部分主体写“无质检相关专利”或“专利全部聚焦于……”，超出了样本支持的范围。应明确“所提供样本中未见”，按方向和相关性选择样本，并检查结论范围，而不能把引用 ID 合法视为内容质量通过。

### 3.4 返回体较大

本次运行状态保存成 JSON 文件后约 11.96 MB（十进制），包括完整快照与证据。当前事件也携带状态，应在页面接入前评估工作集独立读取、摘要状态和分页，避免频繁传输完整材料。此数值是本地 JSON 文件大小，不是压缩网络流量或数据库物理占用。
