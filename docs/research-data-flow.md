# 研究数据流

AI 对话按“思考 → 回答说明 → 方向卡片”展示。开启深度思考时，模型返回的 `reasoning_content` 实时展开，进入正文输出后自动折叠；首轮与追问均先生成 `reply` 说明。服务从 JSON 流中解码 `reply`，通过 `answer_progress` 事件逐步显示正文，完整输出与研究计划校验通过后才展示方向卡片。思考与回答事件持久化并支持回放，关闭思考时直接输出正文。新字段使用明确的空值和状态，不为旧记录补写说明或思考内容。

对话提示词集中在 `prompts.py`：按问题复杂度自然解释和比较，允许通用知识与注明前提的推测，公司或产品只能作为背景例子或待核实线索，不能冒充本次检索结果。探索意图可以主动生成候选卡片，纯解释不替换卡片；已选计划仍需用户应用修改。结构化检索与结果分析继续遵守来源和引用约束，用户本轮请求与参考材料中的指令分开处理。

输入技术方向 → 生成方向与描述 → 确认方向 → 生成内部检索条件 → Google Patents 中国专利网页 → 专利事实入库 → Top 20 权利人 → 等待开始企业发现 → 天眼查企业接口 → 企业候选独立入库 → Agent 解析主体 → 系统展开相关专利 → 研究分析。

工作台分为四个独立地址：`/research/:projectId/plan`、`patents`、`companies`、`report`，通过 `runId` 查询参数选择轮次。左侧按项目列出研究，顶部切换流程和轮次；导航只切换页面，不触发采集。点击确认计划和开始企业发现后，主体解析与报告生成自动完成，不再提供人工确认、拒绝或跳过步骤。

计划页左侧展示和编辑方向名称、描述，支持 1–3 个方向；右侧显示 AI 对话、过程与底部输入框。桌面端使用 `react-resizable-panels` 拖动调整宽度并记住比例，两侧独立滚动；窄屏上下排列。初次模型仅生成方向；确认后由独立 `search_planner` 节点根据最终方向、描述及研究上下文生成关键词、排除词、IPC 和年份，再进入专利采集。检索条件生成失败不会采集；显式重试从该节点恢复，无需再次确认方向。专利检索记录仍展示实际使用的检索词。

专利阶段结束后，系统按规则相关性、去重专利数、最近公开年份和稳定 ID 固化 Top 20 境内企业型权利人。采集任务停在 `awaiting_companies`，研究流程停在 `company_gate`；此时可查看专利快照，但没有查询企业或发布最终快照。`start_companies` 动作继续企业采集，随后自动完成 Agent 主体解析、确定性专利展开和报告生成。企业查询结果按统一社会信用代码独立去重，搜索命中不表示专利归属。

过程摘要记录真实生成阶段与最终方向依据。每次搜索的方向、关键词、页码、来源、结果数量及失败状态写入 `ingestion.event`，通过持久化游标转入研究事件，再由经过字段筛选的 SSE／历史接口提供给前端。各页只展示所属阶段记录，刷新、断线重连和重试可继续回放；旧任务不补造缺失的历史记录。

计划页的追问继承历史需求和上一轮计划，使用新的运行 ID，原轮次只读。`app.research_run.context` 保存创建时的上下文；项目锁、父轮次校验和幂等键避免多标签页并发创建分支。执行中或有待处理动作时，不允许开启新轮次。

确认前允许保存项目、任务和计划，禁止采集写入。采集期间按条目保存，同一任务断点恢复；公司复用有效缓存时仍记录本次研究来源。企业查询目标首次开始时固化，暂停、重试与恢复不会改变。完成时保存不可变快照，后续分析使用该快照。

累计库从事实表查询；公开编号及统一社会信用代码负责去重，来源关联保留每次研究和观察时间。进行中、暂停和完成的数据分别标注状态。累计数据更新不会覆盖已有研究结论。

本次 `browser-v2` 不兼容旧研究。升级本地环境时先执行 `pnpm --filter @tech-scout/api prisma:migrate` 和 `pnpm migrate:research`，再执行 `pnpm reset:research:v2`；该命令永久清空研究、采集、专利、企业、快照和检查点数据，但保留账号与登录会话。
