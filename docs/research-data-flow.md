# 研究数据流

输入技术方向 → 生成方向与描述 → 确认方向 → 生成内部检索条件 → Google Patents 中国专利网页 → 专利事实入库 → 等待开始企业发现 → 天眼查企业接口 → 企业事实入库 → 确认主体并生成报告 → 研究分析。

工作台分为四个独立地址：`/research/:projectId/plan`、`patents`、`companies`、`report`，通过 `runId` 查询参数选择轮次。左侧按项目列出研究，顶部切换流程和轮次；导航只切换页面，不触发采集。点击确认计划、开始企业发现、确认主体并生成报告，才会执行后续阶段。即使没有待核验主体，也要主动点击生成报告。

计划页左侧展示和编辑方向名称、描述，支持 1–3 个方向；右侧显示 AI 对话、过程与底部输入框。桌面端使用 `react-resizable-panels` 拖动调整宽度并记住比例，两侧独立滚动；窄屏上下排列。初次模型仅生成方向；确认后由独立 `search_planner` 节点根据最终方向、描述及研究上下文生成关键词、排除词、IPC 和年份，再进入专利采集。保留原 `Plan` 数据格式兼容历史任务，确认时清空旧检索词，检索条件生成失败不会采集；显式重试从该节点恢复，无需再次确认方向。专利检索记录仍展示实际使用的检索词。

专利阶段结束后，采集任务停在 `awaiting_companies`，研究流程停在 `company_gate`；此时可查看专利快照，但没有查询企业或发布最终快照。`start_companies` 动作继续企业采集，企业完成后停在 `awaiting_entities`，由 `resolve_entities` 动作进入分析。旧采集任务保留原执行边界，新任务采用分阶段流程。

过程摘要记录真实生成阶段与最终方向依据。每次搜索的方向、关键词、页码、来源、结果数量及失败状态写入 `ingestion.event`，通过持久化游标转入研究事件，再由经过字段筛选的 SSE／历史接口提供给前端。各页只展示所属阶段记录，刷新、断线重连和重试可继续回放；旧任务不补造缺失的历史记录。

计划页的追问继承历史需求和上一轮计划，使用新的运行 ID，原轮次只读。`app.research_run.context` 保存创建时的上下文；项目锁、父轮次校验和幂等键避免多标签页并发创建分支。执行中或有待处理动作时，不允许开启新轮次。

确认前允许保存项目、任务和计划，禁止采集写入。采集期间按条目保存，同一任务断点恢复；公司复用有效缓存时仍记录本次研究来源。完成时保存不可变快照，后续分析使用该快照。

累计库从事实表查询；公开编号及统一社会信用代码负责去重，来源关联保留每次研究和观察时间。进行中、暂停和完成的数据分别标注状态。累计数据更新不会覆盖已有研究结论。

更新已有环境时，先执行 `pnpm --filter @tech-scout/api prisma:migrate` 和 `pnpm migrate:research`，再重启 API 与研究服务。新增字段和采集阶段表结构均为增量迁移；只更新代码而不迁移会导致创建研究时数据库字段缺失。
