# 按需采集架构

Web → NestJS → Research（Intelligence + Acquisition）→ Google Patents / 天眼查企业。

NestJS 持有账号和研究项目，统一研究服务使用持久化状态图完成规划、计划确认、采集等待、企业核对、分析与结果；同一进程内的采集 worker 串行使用独立 Chrome 登录配置，按来源限速并保存断点。两个模块直接调用，不再经过本机 HTTP。

数据库按职责划分：`app` 保存账号、项目和页面投影；`agent_runtime` 保存图检查点、预算与执行事件；`ingestion` 保存已确认采集计划、条目和企业缓存；`catalog_v2` 保存去重事实、研究来源、进行中的关系投影与完成时不可变快照。

只有确认计划后才创建采集任务。条目与事实、研究来源、关系投影在同一事务写入。累计库查询事实表；各次研究分析读取本次快照，不因其他任务的新数据而变化。

企业身份与专利权利人分别核对。自动关联要求企业身份及当前权利人名称相符，列表名称不能独立证明当前归属。人工核对决定及证据保存在对应研究中，不静默改写其他研究。

累计库接口为 `/api/v1/library/{companies|patents}`、对应 `/:id` 详情及 `/runs` 来源选项。列表参数为 `page`、`pageSize`、`query`、可选 `runId`；空库返回 200 和空列表。列表不携带专利正文，详情提供摘要、权利要求、说明书、工商字段及网页来源。接口继续要求登录，累计库沿用原目录的共享可见性，研究内容仍按账号隔离。

采集失败保留已取得的事实，页面显示所属任务状态；暂停与继续复用原任务。登录或验证码问题进入等待，不伪造结果、不自动扩大检索范围。
