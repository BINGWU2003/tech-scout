# 按需网页采集

数据源为万方专利网页和风鸟网页。旧离线管道、旧目录及其历史研究已退出运行流程。

## 流程与入库时机

1. 用户创建研究、输入技术方向。此时仅保存研究任务、模型生成的检索计划，不创建采集任务，不写公司或专利事实。
2. 用户确认检索范围后，同一个 `run_id` 创建采集任务。
3. 本机 Python worker 串行访问万方专利检索页和公开详情页，按公开号去重并逐条保存详情；多个方向轮流分页，共最多 100 条。排除词不发送给万方，只在保存后的文本上筛选。
4. 从专利原始参与方名称提取企业检索线索，在风鸟查询、核对现名和曾用名，并保存信用代码及工商资料。英文主体仅在已有企业的英文名得到验证时关联；未匹配主体继续保留待核验。
5. 保存本轮不可变快照，回到同一个研究任务进行企业身份复核和技术分析。用户可以跳过未确认主体。人工确认保存在研究运行的确认记录中，不覆盖采集时的源快照。

空数据库可以从第 1 步开始，不依赖预先生成公司、专利、技术领域或发布目录。目录页面显示最近完成的采集快照；各研究页面展示该研究自己的快照。源事实表跨任务去重保存。

## 本机启动

- `uv sync --project services/research`
- 复制 `services/research/.env.example` 为 `.env`，配置研究与采集数据库连接、内部令牌及模型服务。
- 网页采集是唯一数据来源，不需要来源模式开关。
- `pnpm migrate:research` 初始化 `agent_runtime`、`ingestion` 和 `catalog_v2` schema。
- 给 `CATALOG_DATABASE_URL` 中的只读角色授予新 schema 的 USAGE 和表 SELECT 权限。连接必须指向同一数据库。
- `pnpm login:research` 打开专用 Chrome。登录风鸟后停留几秒，再关闭此窗口。万方基础书目详情无需登录；采集器不访问要求登录的在线阅读或下载入口。
- 分别启动 `pnpm dev:research`、`pnpm dev`。

统一研究服务仅监听本机 8001，所有接口要求内部 Bearer 令牌。采集协调器通过进程内接口调用 worker，不再监听 8002。Windows 数据库事件循环和浏览器子进程循环分开运行。不要同时启动多个使用同一专用浏览器配置的实例；数据库锁也会阻止第二个 worker。

专用配置默认为用户目录下 `.tech-scout/browser-profile`。其中 `tech-scout-session.json` 包含登录材料，只保存在本机，不应提交 Git、上传、分享或写入研究数据库。用户账号导航内容不属于业务来源；保存的专利材料只包含书目字段与正文，企业来源只保留工商信息表。

## 数据与恢复

- `ingestion.job`：确认后的任务、进度、错误、状态。
- `ingestion.item`：本轮发现记录、页检查点、已完成专利与企业结果。
- `catalog_v2.patent`：公开号唯一，公开日与授权日分开，缺失日期为 null。
- `catalog_v2.company`：统一社会信用代码唯一；名称相似不作为唯一键。
- `catalog_v2.release`：本轮不可变快照，以研究运行 ID 为版本号。

暂停会停止后台浏览器任务。恢复复用已完成条目；失败不会自动生成替代数据。429 尊重退避时间，验证码、登录失效、解析异常会进入等待。网络错误最多重试三次。任一未完成的详情保留为待恢复状态，当前版本不会静默跳过失败项并发布“完整”结果。

万方列表名称与详情中的“申请/专利权人”分别保留。只有风鸟身份匹配且详情权利人匹配时，才自动建立公司与专利的关系；其余交给研究中的主体复核。不能从中国公开号或中文公司名直接推断公司国家，也不能把专利命中等同于产品能力。

模型预算不计网页采集等待时间，采集调用另有六小时上限。人工等待不计时；重试沿用已有预算。

## 验证

- `pnpm test:research`：万方网页结构、同名/曾用名匹配、列表与详情冲突、100 条中断恢复及研究工作流。
- 配置指向**独立测试库**的 `TEST_ACQUISITION_DATABASE_URL` 后运行上述测试，可验证真实数据库唯一性、暂停以及快照不可变性。
- `uv run --project services/research pytest services/research/tests/intelligence` 包含空库计划确认门禁测试。
- `pnpm validate` 检查 TypeScript 契约、页面、API 和构建。未配置相应独立数据库的端到端测试会跳过，不能视为已通过。

真实站点验收需单独记录来源访问结果。测试夹具的 100 条通过不代表网站已完成 100 条采集。若来源要求验证，应先处理等待原因，再使用原任务恢复。

## 累计库与旧数据清理

累计库读取事实表，并通过 `record_source` 追溯研究、方向、网页、观察时间。`run_projection` 提供正在采集的关系投影；完成快照保持不可变。

旧离线管道与目录接口已移除。停服务后运行 `cleanup_legacy.py --apply` 清理明确属于旧来源的研究及旧表，未知来源记录保留并报告。更换网页来源时运行 `reset_source_data.py --apply` 清空全部采集检查点、事实、企业缓存与快照，原任务会重置为待执行。两个脚本默认都只盘点。来源重置不会修改用户、研究历史或浏览器登录资料。本地旧文件使用逐文件清单清理，不删除共享数据根目录。

该记录来自迁移前的 Google Patents 采集器，仅作为历史数据说明，不代表当前万方采集器的验收结果。11 组自动关系之外的主体不会强制合并；例如 `CN111370751B` 的中文列表企业与详情当前权利人不同，未自动关联。`CN111933894B` 与安普瑞斯（无锡）有限公司的名称及当前权利人匹配，自动关联。

这项验收验证的是网页采集、保存、复用和身份处理，不等同于模型对全部结果完成了业务相关性审核。前端确认门禁、研究工作流及数据库/API 投影另有自动化测试。

可复跑 `uv run --project services/research python services/research/scripts/acceptance.py`。脚本会在本机 `.local/acceptance.json` 记录专用数据库与运行 ID，恢复复用该记录，不连接日常库写入采集事实。
